# 지시서 02 — 생활비·버킷 점검 계산 + 대시보드 카드

- 프로젝트: 은퇴포트폴리오 AI (retirement-portfolio-ai.vercel.app)
- 스택: React(Vite) + FastAPI(Vercel experimentalServices) + Supabase(서버 전용 키, 전체 RLS)
- 실행: Claude Code 단일 세션 (서브에이전트 사용 안 함)
- 참조: `docs/withdrawal-system/00_design.md` 4.1, 4.2, 4.8절만 참고 (범위 밖 기능은 구현하지 않는다)
- 선행 조건: 지시서 01, S1이 main에 병합된 상태. main에서 `feature/bucket-check` 브랜치를 만든다.

---

## 1. 목적

지시서 01에서 입력한 데이터로 다음 질문에 답하는 **계산**과 **표시**를 만든다.

1. 투자자산에서 매년 꺼내야 하는 돈(순인출 필요액)은 얼마인가?
2. 1버킷·2버킷·전체 자산으로 생활비를 몇 년 버틸 수 있는가? 규칙(R-01, R-02) 기준으로 충분한가?
3. 현재 인출률은 인출 시작 시점 대비 어느 수준인가? 가드레일(R-05, R-06) 범위 안인가?

**이번 범위는 "현황 점검"까지다.** 어디서 얼마를 인출할지 판단하는 로직(지시서 03), 수익률·물가·시나리오 반영(04·05), AI 설명(06)은 포함하지 않는다.

지시서 01의 미해결 사항 2건도 함께 처리한다.
- 실효 버킷 기준 확정 (재지정값과 BUCKET_MAP의 관계)
- 프론트엔드에 복제된 버킷 기본값(`DEFAULT_BUCKET`) 제거, 서버 기준으로 일원화

## 2. 진행 방식 (단계별 중단점)

각 단계가 끝나면 **작업을 멈추고 보고한 뒤 사용자 승인을 받아 다음 단계로 넘어간다.**

| 단계 | 내용 | 끝나면 |
|---|---|---|
| A | 작업 전 조사 (3장), 코드 수정 없음 | 보고 후 중단 |
| B | 계산 모듈 + pytest (4장) | 보고 후 중단 |
| C | API + 버킷 기본값 서버 일원화 (5장) | 보고 후 중단 |
| D | 화면: 대시보드 카드 + 인출 설정 "점검 결과" 탭 (6장) | 보고 후 중단 |
| E | 자체 검증 (9장) + 최종 보고 (10장) | 종료 |

**Git 규칙**: 단계마다 커밋. main 직접 커밋·푸시 금지. 푸시와 PR 생성은 사용자 승인 후 진행하고, 병합은 사용자가 한다.

**DB 변경 없음**: 이번 작업은 마이그레이션을 만들지 않는다. 필요하다고 판단되면 A단계에서 사유와 함께 보고하고 승인을 받는다.

## 3. 작업 전 조사 (단계 A, 보고만)

1. **기존 버킷 관련 기능**: `bucket_snapshots` 테이블의 용도와 기록 주체, `withdrawal_strategy` 라우터, 리밸런싱·대시보드에서 버킷을 표시·계산하는 위치. 이번에 만들 계산과 겹치거나 숫자가 다르게 나올 수 있는 지점을 정리한다.
2. **`withdrawals` 테이블**: 컬럼 구조, 최근 12개월 실제 인출액 합계를 계산할 수 있는지, 투자자산 외의 출금이 섞여 있는지.
3. **"투자자산 총액"의 기존 정의**: 대시보드 등에서 총액을 계산하는 방식(`assets` 활성 합계인지, `real_assets` 포함 여부). 이번 계산은 `assets` 중 `is_active=true`의 `current_value` 합계를 기본으로 하되, 기존 정의와 다르면 보고한다.
4. **대시보드 구조**: 카드 컴포넌트를 추가할 위치와 방식. 기존 카드를 수정하지 않고 import 1줄과 JSX 1줄 수준으로 끼워 넣을 수 있는지.
5. **`DEFAULT_BUCKET` 사용 위치**: 프론트엔드에서 참조하는 모든 파일과 테스트.
6. **현재 데이터 입력 상태**: 값은 출력하지 말고 **건수만** 확인한다. `withdrawal_baseline` 존재 여부, `cashflow_items` 유형별 건수, `holding_profiles` 건수, 버킷 재지정 건수.

**보고 후 중단한다. 승인 전에는 어떤 파일도 만들거나 수정하지 않는다.**

## 4. 계산 모듈 (단계 B)

`backend/withdrawal_check.py`(이름은 기존 관례에 맞춰 조정 가능)에 **순수 함수**로 구현한다.

### 4.0 공통 원칙
- **모든 함수는 기준일 `as_of: date`를 인자로 받는다.** 계산 모듈 안에서 `date.today()`를 호출하지 않는다. 오늘 날짜는 라우터에서만 넣는다. (날짜 의존 테스트 실패를 다시 만들지 않기 위함)
- DB 접근은 하지 않는다. 입력은 파이썬 자료구조, 출력은 dict 또는 dataclass.
- 규칙 임계값은 `ips_rules`의 `parameters`에서 받은 값을 인자로 쓴다. 코드에 상수로 두지 않는다. 규칙이 `enabled=false`면 해당 판정은 `null`(미판정)로 둔다.
- 0으로 나누는 경우는 오류가 아니라 `null`과 사유 코드로 반환한다.

### 4.1 실효 버킷
- `effective_bucket = holding_profiles.bucket`(재지정값)이 있으면 그 값, 없으면 `BUCKET_MAP[asset_type]`.
- 출처도 함께 반환한다: `bucket_source = "override" | "default"`.
- `BUCKET_MAP`은 import만 하고 수정하지 않는다.
- 기존 리밸런싱·대시보드의 버킷 표시는 **변경하지 않는다.** 새 점검 기능만 실효 버킷을 쓴다. 두 기준이 다를 수 있다는 점은 화면에 안내한다(6장).

### 4.2 순인출 필요액
- 유효 항목: `start_date`가 없거나 `as_of` 이전·당일이고, `end_date`가 없거나 `as_of` 이후·당일인 항목.
- 연간 필수생활비 = 필수 월액 합 × 12. 선택생활비, 정기수입도 같은 방식.
- **순인출 필요액(전체)** = max(0, 필수 + 선택 − 정기수입)
- **순인출 필요액(필수)** = max(0, 필수 − 정기수입)
- 개시 전 정기수입은 합산하지 않고, 별도로 "예정 수입" 목록(이름, 월액, 시작일)을 반환한다.
- 물가 상승은 반영하지 않는다(04·05 범위). 출력의 가정 목록에 명시한다.

### 4.3 버킷별 잔액과 커버 연수
- 활성 자산의 `current_value`를 실효 버킷별로 합산한다.
- 커버 연수는 전체 기준과 필수 기준 각각 계산한다.
  - 1버킷 연수 = 1버킷 잔액 ÷ 순인출 필요액
  - 1+2버킷 누적 연수 = (1버킷 + 2버킷) ÷ 순인출 필요액
  - 전체 연수 = 투자자산 총액 ÷ 순인출 필요액 (**수익률 0% 가정 단순 계산**임을 명시)
- 순인출 필요액이 0이면 연수는 `null`, 사유 `no_net_need`.

### 4.4 버킷 규칙 판정 (R-01, R-02)
- R-01: 1버킷 연수(전체 기준)가 `min_years` 미만이면 `below_min`, `target_years` 미만이면 `below_target`, 그 이상이면 `ok`.
- R-02: 2버킷 **단독** 연수가 `target_years` 미만이면 `below_target`, 아니면 `ok`.
- 목표까지 부족액(참고) = max(0, target_years × 순인출 필요액 − 해당 버킷 잔액). 거래 지시가 아니라 참고 수치다.
- 경계값은 "이상이면 충족"으로 한다(`min_years`와 같으면 `below_min`이 아님).

### 4.5 인출률과 가드레일 (R-05, R-06)
- 초기 인출률 = `initial_annual_withdrawal` ÷ `initial_portfolio_value` (기준점이 없으면 `null`, 사유 `baseline_missing`)
- **현재 인출률(계획 기준)** = 순인출 필요액(전체) ÷ 현재 투자자산 총액 ← 가드레일 판정에 사용
- **현재 인출률(실적 기준, 참고)** = 최근 12개월 `withdrawals` 합계 ÷ 현재 투자자산 총액. A단계 조사 결과 계산이 부적절하면 제외하고 보고한다.
- 비율 = 현재(계획 기준) ÷ 초기
  - `upper_multiplier` **초과**면 `upper_breach`, 참고 감액 = 연간 선택생활비 × `cut_ratio` (필수생활비는 대상 아님)
  - `lower_multiplier` **미만**이면 `lower_breach`, 참고 증액 여지 = 순인출 필요액 × `raise_ratio`
  - 그 외 `within`. 경계값과 같으면 `within`.
- 판정은 "규칙 충족 여부"까지만 한다. 실제 감액 결정과 인출 실행 판단은 지시서 03 범위다.

### 4.6 데이터 완성도
- 속성이 없어 기본 버킷이 적용된 활성 자산의 건수와 **금액 비중**
- 기준점 입력 여부, 생활비 항목 존재 여부
- 필수 데이터(기준점, 생활비)가 없으면 계산 가능한 부분만 반환하고, 없는 항목은 `null`과 사유 코드로 표시한다.

### 4.7 출력 구조 (예시, 세부는 조정 가능)
```
{
  as_of, 
  net_need: {annual_total, annual_essential, monthly_total, upcoming_income[]},
  buckets: [{bucket, value, years_total, years_essential, asset_count}],
  cumulative: {b1_b2_years_total, all_years_total},
  rules: {R-01: {status, shortfall}, R-02: {...}, R-05/R-06: {status, ratio, suggestion_amount}},
  withdrawal_rate: {initial, current_plan, current_actual},
  completeness: {default_bucket_count, default_bucket_value_share, baseline_set, cashflow_set},
  assumptions: ["수익률 0% 가정", "물가 상승 미반영", "투자자산 = assets 활성 합계", ...],
  reasons: [{field, code}]
}
```
관측값(잔액, 입력값)과 가정·파생값을 구분할 수 있게 한다.

### 4.8 테스트 (pytest, 운영 DB 사용 금지)
- 모든 테스트는 `as_of`를 고정해서 호출한다.
- 필수 케이스: 재지정 vs 기본 버킷, 비활성 자산 제외, 유효기간 경계(시작일 당일, 종료일 당일, 개시 전 수입), 순인출 필요액이 0 또는 음수, 0 나누기, R-01 경계(min과 같음, target과 같음), R-02, 가드레일 경계(배수와 같음), 규칙 비활성화, 기준점 없음, 실적 인출 데이터 없음.

## 5. API (단계 C)

### 5.1 점검 API
- `GET /withdrawal-check`: DB에서 활성 자산, 속성, 생활비 항목, 기준점, 규칙 R-01·R-02·R-05·R-06, (가능하면) 최근 12개월 인출 실적을 읽어 계산 모듈에 넘기고 결과를 반환한다. `as_of`는 라우터에서 `date.today()`로 넣는다.
- 선택 쿼리 파라미터 `as_of`(YYYY-MM-DD)를 허용한다. 검증·재현용이다.
- 기존 인증(`require_user`)이 등록부에서 일괄 적용되는지 확인한다.

### 5.2 버킷 기본값 서버 일원화
- 인출 설정의 보유상품 그리드가 쓰는 응답(목록 또는 `/missing`)의 **모든 행**에 `default_bucket`, `effective_bucket`, `bucket_source`가 들어가게 한다.
- 프론트엔드의 `DEFAULT_BUCKET`과 관련 테스트를 제거하고 서버 값을 사용한다.
- 지시서 01에서 만든 파일의 수정은 허용한다. 수정 파일과 사유를 보고한다.

### 5.3 API 테스트
- 가짜 supabase와 인증 override(`conftest.py`)로 응답 구조, 인증 없는 요청 401, `as_of` 파라미터 검증을 확인한다.

## 6. 화면 (단계 D)

### 6.1 대시보드 "인출 점검" 카드
- 기존 대시보드에 카드 1개를 **추가만** 한다. 기존 카드의 코드·순서·스타일은 바꾸지 않는다.
- 표시 내용:
  - 순인출 필요액 (연·월)
  - 1버킷 N.N년 / 1+2버킷 N.N년. R-01 상태 색상 표시(`ok` 기본색, `below_target` 주의, `below_min` 경고)
  - 인출률: 초기 X.X% → 현재 Y.Y%, 가드레일 범위 안/밖 표시
  - 기준일과 "수익률·물가 미반영 단순 계산" 문구
  - 데이터 미완성 시 "기본 버킷 적용 자산 N개(금액의 X%)" 또는 "인출 기준점 미입력" 안내와 인출 설정 화면 링크
- 카드를 누르면 인출 설정의 "점검 결과" 탭으로 이동한다.

### 6.2 인출 설정 "점검 결과" 탭 (5번째 탭)
- 버킷별 자산 목록: 자산명, 금액, 실효 버킷, 출처(재지정/기본)
- 생활비 구성: 필수/선택/정기수입, 예정 수입
- 규칙 판정 상세: R-01·R-02 부족액(참고), R-05·R-06 참고 금액. **"참고 수치이며 실행 판단은 규칙 엔진(예정)에서 제공"** 문구
- 안내 문구: "이 화면의 버킷은 재지정값을 반영합니다. 기존 리밸런싱 화면의 버킷은 자산유형 기준입니다."
- 가정 목록 표시

### 6.3 공통
- 비율·연수 표시 형식은 기존 앱과 맞추고, 포맷 함수는 한 곳에 두어 단위 테스트를 추가한다.
- `null` 값은 "-"와 사유 툴팁으로 표시한다. 0으로 표시하지 않는다.
