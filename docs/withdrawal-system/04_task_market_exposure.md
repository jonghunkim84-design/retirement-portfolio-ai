# 지시서 04 — 시장 신호 수집 + 노출도 지도 + 단일 시나리오

- 프로젝트: 은퇴포트폴리오 AI (retirement-portfolio-ai.vercel.app)
- 스택: React(Vite) + FastAPI(Vercel experimentalServices) + Supabase(서버 전용 키, 전체 RLS)
- 실행: Claude Code 단일 세션 (서브에이전트 사용 안 함)
- 참조: `docs/withdrawal-system/00_design.md` 4.4, 4.5절만 참고 (범위 밖 기능은 구현하지 않는다)
- 선행 조건: 지시서 03과 설정 화면 표시 수정이 main에 병합된 상태. main에서 `feature/market-exposure` 브랜치를 만든다.

---

## 1. 목적

"시장이 변하면 내 자산과 생활비에 어떤 영향이 있는가"에 답한다. 구성은 네 가지다.

1. **시장 신호 수집**: 핵심 지표의 이력을 저장한다(관측값, 출처·기준일 포함).
2. **노출도 지도**: 보유 자산이 금리·환율·주가(지역별)에 얼마나 노출돼 있는지 금액으로 보여 준다.
3. **단일 시나리오**: 금리·주가·환율·물가 충격을 하나씩 적용했을 때 자산 변화와 **필수생활비 충당 연수** 변화를 계산한다.
4. **시장 국면 자동 계산**: 3버킷 자산의 지역 구성으로 가중한 고점 대비 하락률을 계산해, 분기 판단(03) 화면에 **기본값으로 채워 준다.** 사용자는 확인하거나 수정할 수 있다.

**원칙: 예측하지 않는다.** 관측값은 관측값으로, 시나리오는 "가정하면 이렇게 된다"로만 보여 준다. 데이터가 없으면 추정해서 채우지 않고 "없음"과 사유를 표시한다.

## 2. 이번 지시서에 반영된 결정 사항

| # | 사안 | 결정 |
|---|---|---|
| 1 | 시장 국면 기준 | 지수 하나가 아니라 **3버킷 자산의 지역별 금액으로 가중한 하락률**을 쓴다. 각 지역은 대응 기준지수의 **현지 통화 기준** 하락률을 쓴다(시장 상황 판정용). 원화 환산 손익은 시나리오에서 다룬다. |
| 2 | 지역 표기 | 사용자가 입력한 값: 한국, 미국, 글로벌, 신흥국, 일본, 중국, 유럽. 지역→기준지수 대응은 DB 테이블로 관리한다. 대응이 없는 지역은 계산에서 제외하고 금액 비중과 함께 표시한다. |

| 4 | 분기 판단 연계 | 판단 엔진(`decision_engine.py`)의 로직은 바꾸지 않는다. 화면이 자동 계산값을 입력칸에 채우고, 저장되는 입력 스냅샷에 출처(`auto`/`manual`)와 구성 내역을 함께 남긴다. |
| 5 | 복합 시나리오·순서위험 | 05 범위. 04는 단일 충격만 다룬다. |
| 6 | 계좌 제약 반영 버킷 | 03 미해결 11번은 이번 범위가 아니다(별도 지시서). |

## 4. 작업 전 조사 (단계 A, 보고만)

1. **데이터 원천 확인 (실제 조회 테스트)**. 아래 지표마다 사용 가능한 원천, 심볼, 이력 기간, 조회 시간, 새 API 키 필요 여부를 표로 보고한다. 이미 의존성에 있는 FinanceDataReader·pykrx를 우선 검토한다.
   - 주가지수: KOSPI, S&P500, 그리고 글로벌·신흥국·일본·중국·유럽의 기준지수 후보(지수 직접 조회가 안 되면 대표 ETF 가격을 대용으로 쓸 수 있는지)
   - 금리: 한국 기준금리, 국고채 3년·10년, 미국 국채 10년
   - 환율: 원/달러 (보유 외화 자산에 다른 통화가 있으면 그 통화도)
   - 물가: 한국 소비자물가 상승률(전년 동월 대비)
   - 새 API 키(한국은행 ECOS, FRED 등)가 필요한 지표는 **발급하지 말고** 필요 여부와 대안을 보고한다.
2. **Vercel 제약**: 현재 요금제의 크론 개수·빈도 제한, 함수 실행 시간 제한. 수집을 새 크론으로 할지, 기존 일일 크론에서 호출할지, 화면의 "갱신" 버튼으로 할지 제안한다. 기존 `/alert/daily` 로직은 수정하지 않는 것을 원칙으로 한다.
3. **자산 속성 완성도** (건수와 금액 비중만, 금액 제외)
   - 3버킷 자산 중 지역 입력 건수와 비중, 입력된 지역 값의 종류
   - 채권(`bond`) 중 수정듀레이션 입력 건수, 만기만 있는 건수, 둘 다 없는 건수
   - tdf·fund 중 주식 비중 입력 건수
   - income 중 금리 민감도 입력 건수
   - 외화 자산의 통화 종류, 환헤지 여부 입력 상태
4. **기존 시세 수집 코드**(`price.py`): 재사용할 수 있는 부분(라이브러리 호출 방식, 오류 처리). import만 허용한다.
5. **03 연계 지점**: 분기 판단 화면과 `/decision-engine/run`의 `market_input` 구조. 자동 계산값을 넣으려면 어디를 얼마나 바꿔야 하는지.

**보고 후 중단한다. 승인 전에는 어떤 파일도 만들거나 수정하지 않는다.**

## 5. 데이터 모델 (단계 B, 신규 테이블만)

기존 관례를 따른다: bigint identity PK, `text + CHECK`, `created_at/updated_at`, `BEGIN; … COMMIT;`, 신규 테이블 RLS 활성화(정책 없음, 서버 전용 키만 접근).

### 5.1 `market_series`: 지표 정의

| 컬럼 | 설명 |
|---|---|
| code | 내부 코드, UNIQUE (예: `IDX_KOSPI`, `RATE_KTB10Y`, `FX_USDKRW`, `CPI_KR_YOY`) |
| name | 표시 이름 |
| category | `equity_index`, `rate`, `fx`, `inflation` |
| unit | `index`, `percent`, `krw_per_usd` 등 |
| source, source_symbol | A단계에서 확정한 원천과 심볼 |
| is_proxy | 지수 대신 ETF 가격을 쓰는 경우 true |
| enabled | 수집 여부 |

### 5.2 `market_observations`: 관측값

| 컬럼 | 설명 |
|---|---|
| series_code | FK → market_series.code |
| obs_date | 관측일 |
| value | 값 |
| fetched_at | 수집 시각 |
| UNIQUE (series_code, obs_date) | 재수집 시 upsert |

### 5.3 `region_benchmarks`: 지역→기준지수

| 컬럼 | 설명 |
|---|---|
| region | UNIQUE. 한국, 미국, 글로벌, 신흥국, 일본, 중국, 유럽 |
| series_code | FK → market_series.code |

### 5.4 시드와 규칙 파라미터
- `market_series`와 `region_benchmarks` 시드는 A단계에서 확인된 원천만 넣는다. 원천이 없는 지표는 넣지 않는다.
- R-04 `parameters`에 `lookback_days: 365`를 추가한다(기존 `drawdown_threshold` 유지). 규칙 탭 검증에 `30 ≤ lookback_days ≤ 1095`를 추가한다.

## 6. 수집 (단계 C)

- `backend/market_data.py`: 원천별 조회 함수(네트워크)와 저장 함수를 분리한다. 계산 모듈은 네트워크를 쓰지 않는다.
- **증분 수집**: 지표별 마지막 관측일 다음 날부터만 조회한다. 실패한 지표는 건너뛰고 나머지는 계속한다. 결과로 지표별 성공·실패·신규 건수를 반환한다.
- **초기 적재**: 지표별 최근 3년치. 함수 실행 시간 제한을 넘지 않게 지표 단위로 나누어 실행할 수 있어야 한다. 초기 적재는 로컬에서 서버 전용 키로 1회 실행하는 스크립트를 허용한다(신규 테이블에만 쓰기, 사용자 승인 후 실행).
- **갱신 방식**: A단계 제안 중 승인된 방식으로 한다. 어느 방식이든 수집 엔드포인트는 크론이면 `require_cron`, 화면 버튼이면 `require_user`로 보호한다.
- 값이 비정상이면(음수 지수, 전일 대비 급변 등 A단계에서 기준 제안) 저장하지 않고 경고로 반환한다.
- 수집 코드 테스트는 네트워크를 가짜로 바꿔서 한다.

## 7. 계산 모듈 (단계 D)

`backend/market_exposure.py`에 **순수 함수**로 구현한다. 공통 원칙은 02·03과 같다: `as_of` 인자 필수, 모듈 안 `date.today()` 금지(소스 검사 테스트), DB·네트워크 접근 금지, `null`과 사유 코드 반환, 가정 목록 출력.

### 7.1 지표 요약
- 지표별 최신값, 최신 관측일, 1개월·3개월 전 대비 변화(금리는 %p, 지수·환율은 %), 52주 고점 대비 하락률(지수)
- 최신 관측일이 `as_of`보다 일정 기간(일별 지표 7일, 월별 지표 60일) 이상 오래되면 `stale` 표시

### 7.2 가중 하락률 (시장 국면 자동 계산)
- 지역별 하락률 = 1 − (as_of 이전 최신값 ÷ `lookback_days` 기간 최고값)
- 가중 하락률 = Σ(3버킷 자산의 지역별 금액 × 해당 지역 하락률) ÷ 계산에 포함된 3버킷 금액
- 지역 미입력, 대응 지수 없음, 데이터 부족(stale 포함) 자산은 제외하고, 제외 금액 비중과 사유를 반환한다.
- 제외 비중이 50%를 넘으면 결과를 `unreliable`로 표시한다.
- 출력: 가중 하락률, 지역별 내역(지역, 기준지수, 하락률, 금액 비중), 제외 내역, 기준일

### 7.3 노출도 지도
자산마다 다음을 계산하고, 버킷별·전체로 합산한다.

| 노출 | 계산 | 데이터 없을 때 |
|---|---|---|
| 금리 (채권) | 금리 1%p 상승 시 변화액 = −수정듀레이션 × 0.01 × 금액 | 듀레이션이 없고 만기만 있으면 **잔존만기(년)를 듀레이션 대용**으로 쓰고 `assumed` 표시. 둘 다 없으면 제외 |
| 금리 (변동금리 채권, 현금) | 가격 변화 0. 연간 이자 변화 참고값 = 0.01 × 금액 | - |
| 금리 (tdf·fund) | 채권 부분(1 − 주식 비중)에만 적용. 듀레이션 입력이 있으면 사용 | 없으면 금리 노출 제외, 사유 표시 |
| 금리 (리츠·인컴) | 금리 민감도 × 0.01 × 금액 (가정값) | 없으면 제외, 사유 표시 |
| 주가 | 지역별 주식성 금액 (주식, 리츠·인컴, tdf·fund의 주식 부분) | 지역 없으면 "지역 미상"으로 집계 |
| 환율 | 환헤지하지 않은 외화 자산 금액, 통화별 | 통화 미입력 외화 추정 자산은 사유 표시 |

- 출력 문장용 수치: "금리 1%p 상승 시 약 ○원", "원/달러 10% 하락 시 약 ○원", 지역별 주식 노출 금액과 비중
- 데이터 완성도: 항목별 제외 금액 비중

### 7.4 단일 시나리오
프리셋과 사용자 입력 값을 모두 지원한다. 충격은 한 번에 하나만 적용한다.

| 시나리오 | 적용 |
|---|---|
| 금리 ±Δ%p | 7.3의 금리 노출 × Δ |
| 주가 −X% | 모든 지역에 같은 X, 또는 지역별 X. 주식성 금액에 적용 |
| 원/달러 ±Y% | 비헤지 외화 자산에 적용. 외화 자산의 주가 변화는 0으로 둔다(단일 충격) |
| 물가 +Z%p (1년) | 자산 가격은 그대로. `inflation_linked=true`인 생활비 항목만 Z만큼 증가시켜 순인출 필요액 재계산 |

**결과**
- 전체·버킷별·자산별 금액 변화
- 충격 후 버킷별 커버 연수 (**필수생활비 기준**과 전체 기준). 02의 `withdrawal_check` 계산 함수를 충격 반영 입력으로 다시 호출해서 얻는다. 같은 계산을 새로 구현하지 않는다.
- 충격 전후 R-01 상태 변화 (예: `ok → below_target`)
- 가정 목록, 제외 자산과 사유
- 프리셋 기본값: 금리 +1%p / −1%p, 주가 −20%, 원/달러 −10%(원화 강세) / +10%, 물가 +2%p. 프리셋은 코드 상수가 아니라 설정 파일이나 DB에 둔다(A단계에서 방식 제안).

### 7.5 최근 시장 변화의 영향 (신호 → 내 자산)
- 실제 관측된 1개월 변화를 7.3 노출에 곱해 **추정 영향액**을 계산한다. 예: 미국 10년물 1개월 +0.3%p × (미국 채권 금리 노출) = 약 ○원.
- 출력 구조: 관측된 변화 → 내 노출 → 추정 영향 → 생활비 연수 영향(해당 시). 문장은 화면에서 조립한다.
- 국내·해외 금리 구분: 채권 자산의 통화(또는 지역)로 대응 금리 지표를 고른다. 대응이 불명확하면 해당 자산은 제외하고 사유를 표시한다.

### 7.6 테스트 (pytest, 네트워크·운영 DB 금지, `as_of` 고정)
- 하락률: 고점 당일, 기간 밖 고점 무시, 데이터 부족, stale
- 가중 하락률: 지역 미입력 제외, 대응 지수 없음, 제외 비중 50% 초과 `unreliable`
- 노출도: 듀레이션 있음, 만기 대용(`assumed`), 둘 다 없음, 변동금리, tdf 분할, 리츠 민감도 없음, 환헤지 제외
- 시나리오: 금리 ±, 주가 균일·지역별, 환율 ±, 물가(연동 항목만 증가), 충격 후 연수와 R-01 상태 변화
- 신호 영향: 국내·해외 금리 대응, 대응 불명확 제외
- 02 계산 함수 재사용 여부(동일 입력 → 동일 결과)

## 8. API (단계 E)

| 경로 | 메서드 | 내용 |
|---|---|---|
| `/market/series` | GET | 지표 정의와 최신값·변화·stale 여부 |
| `/market/series/{code}/history` | GET | 이력(기간 파라미터), 차트용 |

## 9. 화면 (단계 F)

### 9.1 신규 메뉴 "시장·노출" (연금·세금 그룹 또는 자산 그룹, A단계에서 제안)
1. **시장 신호**: 지표 카드(최신값, 1개월 변화, 기준일, stale 경고, 대용 지표 표시). 카드를 누르면 이력 차트. "데이터 갱신" 버튼(승인된 방식일 때).
2. **최근 변화의 영향**: 7.5 결과를 "변화 → 내 노출 → 추정 영향" 카드로. 문구: "관측된 변화에 현재 보유 구성을 곱한 추정치입니다."
3. **내 노출도**: 금리 1%p당 금액, 비헤지 외화 금액, 지역별 주식 노출 표. 데이터 완성도(제외 비중)와 인출 설정 화면 링크.
4. **시나리오**: 프리셋 버튼과 직접 입력. 결과는 금액 변화와 **"필수생활비 N.N년 → M.M년"**을 가장 크게 표시하고, R-01 상태 변화와 가정·제외 목록을 함께 보여 준다. 문구: "예측이 아니라 가정에 따른 점검입니다."

### 9.2 분기 인출 판단 화면 (03) 연계
- 화면을 열면 `/market/regime`으로 가중 하락률을 계산해 입력칸에 채운다. 지역별 내역, 기준일, `unreliable` 여부를 입력칸 옆에 표시한다.
- 사용자는 값을 그대로 쓰거나 수정한다. 수정하면 출처가 `manual`로 바뀐다.
- 판단 실행과 로그 저장 시 `market_input`에 출처, 지역 내역, 기준일을 함께 넘겨 입력 스냅샷에 남긴다.
- 엔진 모듈(`decision_engine.py`)의 판단 로직은 수정하지 않는다. 라우터·화면의 입력 확장만 허용하며, 기존 로그 형식과 호환돼야 한다.

### 9.3 공통
- 모든 수치 옆에 "관측" 또는 "가정" 표시. 문장 조립은 한 곳에서, 단위 테스트 포함.
