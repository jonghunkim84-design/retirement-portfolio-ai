# 은퇴포트폴리오 AI — 인출 중심 자산운영 판단 시스템 설계서 (v0.1)

> 이 문서는 전체 설계의 기준 문서입니다. 실제 구현은 단계별 지시서(01, 02, …)로 한 건씩 진행합니다.
> 이 문서 자체는 구현 지시가 아니며, Claude Code가 각 지시서를 수행할 때 참조하는 배경 문서입니다.
>
> **사용 방법 (Claude Code 단일 세션 기준)**
> - 이 문서와 지시서는 저장소의 `docs/withdrawal-system/` 폴더에 둔다.
> - 지시서마다 새 세션(또는 `/clear` 후)에서 시작하고, 첫 요청은 "`docs/withdrawal-system/0N_*.md` 지시서를 읽고 2장(작업 전 조사)만 수행해 보고해 줘"로 한다.
> - Claude Code는 이 설계서 중 해당 지시서가 가리키는 절만 참고하고, 범위 밖 기능은 구현하지 않는다.

## 1. 배경과 목적

- 사용자는 약 1년 전부터 은퇴자산을 인출하고 있다.
- 기존 앱은 현금·채권·주식·리츠 4개 자산군의 목표 비중과 리밸런싱을 관리한다.
- 부족한 것: (1) 자산군 내부에서 무엇을 보유해야 하는지, (2) 시장 변화가 내 자산과 생활비에 미치는 영향, (3) 그에 따라 무엇을 해야 하는지에 대한 판단 근거.

**시스템이 답해야 할 질문**

1. 앞으로 필요한 생활비를, 자산을 불리한 시점에 팔지 않고 마련할 수 있는가?
2. 각 보유상품이 맡은 역할에 맞는가? 실제 위험(금리·신용·환율·집중도)은 어떤가?
3. 시장이 변했을 때 유지·인출·보충·조정 중 무엇을 해야 하고, 근거는 무엇인가?
4. **이번 분기 생활비를 어느 자산, 어느 계좌에서, 얼마나 꺼내야 하는가?** ← 인출 단계의 핵심 투자 결정

## 2. 설계 원칙

| 원칙 | 내용 |
|---|---|
| 계산과 설명의 분리 | 금액·비율·판단은 FastAPI의 결정론적 계산과 명시적 규칙으로 처리한다. AI(Claude API)는 결과를 설명만 하며, 숫자를 새로 만들거나 규칙을 바꾸지 않는다. |
| 예측이 아닌 점검 | 시장 방향을 예측하지 않는다. 가정된 변화가 일어나면 어떻게 되는지를 계산한다. |
| 사전 규칙 | 행동 기준(IPS, 투자정책서)은 시장이 흔들리기 전에 정해 두고, 시스템은 규칙 충족 여부를 판정한다. 규칙 미충족 시 "현재는 유지"와 근거를 출력한다. |
| 사실·가정 구분 | 모든 화면과 출력에서 관측값(시장 데이터, 잔고)과 가정값(사용자 입력 민감도, 시나리오)을 구분하고 기준일을 표시한다. |
| 설정값 외부화 | 세금·건보료 기준값, 규칙 임계값은 코드 상수로 두지 않고 설정 테이블에 기준일과 함께 저장한다. |
| 기존 기능 보존 | 건보료 시뮬레이터, 세금 가이드, AI 어드바이저, Excel 내보내기는 수정하지 않고 호출·연계만 한다. |

## 3. 전체 구조 (4개 층)

```
[1층] 시장 신호        금리·주가·환율·물가 등 핵심 지표 6~8개, 기준일 포함
        │
[2층] 노출도 지도      보유상품별 역할·버킷·듀레이션·신용·통화·지역·업종·계좌
        │               → 시나리오 충격 시 금액 영향 계산
[3층] 생활비·버킷      순인출 필요액, 버킷별 커버 연수, 현재 인출률 vs 초기 인출률
        │
[4층] 판단 엔진        IPS 규칙 → 인출원 선택, 버킷 보충, 가드레일, 계좌 순서
        │               → 결정 + 근거 + 적용 규칙 ID
[설명] AI 어드바이저    결과를 사람의 언어로 설명 (계산 금지)
[기록] 의사결정 로그    판단·실행 여부·사후 검토
```

## 4. 기능 상세

### 4.1 생활비 점검
- 입력: 필수생활비, 선택생활비(월), 정기수입(국민연금·기타 연금 등, 시작·종료 시점), 물가 연동 여부.
- 계산: **순인출 필요액 = 연간 지출 − 연간 정기수입**. 투자자산은 이 금액만 책임진다.
- 출력: 필수생활비 기준 / 전체 생활비 기준 각각의 버틸 수 있는 기간.

### 4.2 버킷 구조 (4개 자산군의 역할 재해석)

| 버킷 | 구성 | 역할 | 목표 (예시 기본값, 사용자 설정) |
|---|---|---|---|
| 1버킷 | 현금, 단기채(잔존만기 약 2년 이하) | 생활비 지급 | 순인출 필요액 1~2년치 |
| 2버킷 | 중기채, 배당·인컴 성격 자산 | 1버킷 보충용 완충 | 3~7년치 |
| 3버킷 | 주식, 리츠 | 장기 성장, 물가 방어 | 나머지 |

- 보유상품마다 버킷을 지정한다. 자산군 비중(기존)과 버킷 커버 연수(신규)를 함께 보여준다.

### 4.3 보유상품 진단 (자산군 내부 기준)

| 자산군 | 확인 항목 |
|---|---|
| 현금 | 지급 시점, 즉시 인출 가능 여부, 원금 보호 조건, 통화, 금리 |
| 채권 | 만기·수정듀레이션, 고정/변동금리, 신용등급, 통화, 환헤지 여부 |
| 주식 | 국가·업종 분산, 개별 종목 집중도, 상품 간 보유종목 중복, 총보수 |
| 리츠 | 부동산 유형·지역, 부채비율·차환 일정, 분배금 지속성, 금리 민감도 |

- **자산군 내부 2단계 목표 비중**과 허용 폭을 둔다. 예: 채권 내 단기/중기/장기, 주식 내 국내/해외선진/신흥, 리츠 내 국내/해외.
- 중복·집중 분석(ETF 구성종목 기준)은 데이터 확보가 어려우므로 후순위 단계로 둔다.

### 4.4 시장 신호 (1층)
- 핵심 지표만: 기준금리, 국고채 3년·10년, 미 국채 10년, 원/달러 환율, 소비자물가 상승률, 국내·해외 대표 주가지수, 신용스프레드.
- 데이터 소스 후보: 한국은행 ECOS Open API(국내 금리·환율·물가), FRED(미국 지표). 가격 데이터는 기존 앱의 방식을 우선 사용한다.
- 출력은 지표 나열이 아니라 "관측된 변화 → 내 보유상품 노출 → 생활비 영향 → 행동 조건" 순서의 설명 카드.

### 4.5 노출도·시나리오 계산 (2층)
결정론적 근사식으로 계산하고, 사용한 가정을 함께 표시한다.

| 대상 | 근사식 |
|---|---|
| 채권 | 가격 변화율 ≈ −수정듀레이션 × 금리 변화 |
| 해외자산 | 원화 수익률 = (1 + 현지 수익률) × (1 + 환율 변화율) − 1, 환헤지 상품은 환율 효과 제외 |
| 주식 | 시나리오 주가 변화율 × 보유액 (지역별 적용) |
| 리츠 | 주가 충격 + 금리 민감도(사용자 입력 가정값) × 금리 변화 |
| 현금 | 금리 변화 → 재예치 이자 변화 |
| 물가 | 필수생활비 증가 → 버킷 커버 연수 감소 |

- 결과는 손실 금액과 함께 **"필수생활비를 몇 년 충당 가능한가"**, **"언제 어떤 자산을 팔아야 하는가"**로 표현한다.

### 4.6 스트레스 테스트
- 단일 시나리오: 주식 급락, 금리 상승, 물가 상승, 원화 강세, 예상 밖 큰 지출.
- 복합 시나리오: 위 조합 + **인출 초기 연속 하락(순서위험)**: 첫 2~3년 하락이 이어질 때 자산 수명 변화.
- 출력은 예측이 아닌 가정에 따른 점검임을 명시한다.

### 4.7 판단 엔진 (4층, 분기 단위)

**입력**: 이번 분기 순인출 필요액, 버킷별 잔고, 자산군·하위 목표 대비 이탈, 시장 국면, 계좌별 제약.

**처리 순서 (결정론적)**
1. 이번 분기 순인출 필요액 계산 (가드레일 조정 반영).
2. 시장 국면 판정: 주식 기준지수의 고점 대비 하락률이 임계값(예: 15%) 이상이면 "하락 국면".
3. 허용 폭을 초과한 자산군이 있으면 그 초과분에서 먼저 인출한다. (인출이 곧 리밸런싱)
4. 하락 국면이면 3버킷 매도를 금지하고 1버킷에서 인출한다. 1버킷이 최소 수준 미만이면 2버킷에서 인출한다.
5. 그 외에는 목표 대비 가장 많이 초과한 자산군에서 인출한다.
6. 1버킷 보충: 1버킷이 목표 연수 미만이고 하락 국면이 아니면 초과 자산에서 보충한다.
7. 계좌 제약 적용: 연금계좌 수령한도, 사적연금 분리과세 기준, 금융소득 종합과세 기준, 건보료 영향을 확인하고 계좌별 인출 순서를 조정한다. (기존 세금 가이드·건보료 시뮬레이터 로직을 호출, 기준값은 설정 테이블)
8. 매매 전 확인: 세금·수수료·중도해지 제약.

**출력**: 인출 금액, 출처 상품·계좌, 보충 거래, 적용 규칙 ID, 근거 문장용 구조화 데이터, 해당 규칙이 없으면 "현재는 유지"와 사유.

### 4.8 인출액 가드레일
- 현재 인출률 = 연간 인출액 ÷ 현재 투자자산.
- 초기 인출률(인출 시작 시점 기준점) 대비 상단 기준(예: ×1.2) 초과 시 선택생활비 감액 또는 물가 인상분 생략을 권고.
- 하단 기준(예: ×0.8) 미만 시 증액 여지 표시.
- 기준값은 사용자 설정. 필수생활비는 감액 대상에서 제외한다.

### 4.9 AI 설명 레이어
- 기존 AI 어드바이저에 판단 엔진 출력, 시장 신호, 버킷 현황을 컨텍스트로 주입한다.
- 시스템 프롬프트 원칙: 제공된 숫자만 사용, 새 계산 금지, 관측/가정 구분, 규칙 변경 제안은 "검토 제안"으로만 표현.

### 4.10 의사결정 로그
- 분기마다 엔진 판단, 사용자의 실제 실행 여부, 다르게 실행했다면 사유를 기록한다.
- 분기 리뷰 화면: 규칙대로 했을 때와 실제 결과 비교. 감정적 이탈을 줄이고 규칙 자체를 개선하는 근거로 쓴다.

### 4.11 목표 비중 재검토 트리거
- 목표 비중은 단기 뉴스가 아니라 재정 상황 변화(생활비 변화, 정기수입 개시, 큰 지출, 건강·가족 상황)에 연결해 재검토한다.
- 연 1회 정기 재검토 알림.

## 6. 유의사항
- 규칙 임계값과 버킷 연수의 기본값은 예시이며, 실제 값은 사용자가 본인 재정 상황에 맞게 정한다.
- 세금·건보료 기준값은 법령 개정 가능성이 있으므로 기준일과 함께 관리하고, 앱에서 기준일을 표시한다.
- 이 시스템은 개인 의사결정 보조 도구이며 투자 자문을 대체하지 않는다.
